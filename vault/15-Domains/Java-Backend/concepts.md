# 核心概念

记录已经学习、理解或确认的 Java 后端知识。每条知识尽量包含：定义、适用边界、常见误区、最小示例和关联概念。

## 项目主线

### 线上订单履约平台

- 项目目标：完成一个线上订单履约平台。
- 主要模块：`order` 负责订单；`inventory` 负责库存管理；`fulfillment` 负责订单履约。
- 核心流程：用户在线下单后创建订单，系统预占库存，再发送消息通知履约平台处理订单；用户付款后订单进入结束阶段。
- 关联知识：微服务拆分、订单状态机、库存预占、消息队列、异步解耦、幂等、分布式一致性和补偿。
- 当前学习结论：用户能够独立说清项目目标、模块职责和核心业务主线；实现状态与规划内容暂未纳入本次回答。

### 服务拆分与领域边界

- `order` 负责订单管理和订单状态；`inventory` 负责库存管理；`fulfillment` 负责订单履约。
- 三个模块按业务职责和数据归属拆分，各自维护独立数据库，减少直接数据耦合，便于独立扩展和升级。
- “解耦”不代表模块之间没有联系，而是通过 API 调用和消息事件协作；因此会引入网络失败、数据一致性、幂等和补偿等分布式问题。
- 重要边界：`fulfillment` 主要负责履约，不等同于支付管理；支付结果通常由订单域管理，履约模块消费支付结果后创建或推进履约单。

### Gateway 到订单服务的请求链路

- 请求 `/api/orders/{id}` 先到 Gateway；Gateway 通过 `/api/orders/**` 路由谓词匹配订单路由。
- `StripPrefix=1` 去掉第一段 `api`，转发路径变为 `/orders/{id}`。
- `lb://platform-order` 表示根据服务名从 Nacos 发现订单服务实例，再由 LoadBalancer 选择具体实例。
- 请求进入订单服务后，通常继续经过 Controller、Service、Mapper，最终访问订单数据库并返回响应。
- 术语边界：Nacos 在这里承担服务注册与发现，不应简单表述为“订阅 order 服务”。

### `platform-common` 公共模块

- `platform-common` 是被多个微服务依赖的普通公共 `jar`，用于存放跨服务真正一致的共识内容，例如统一响应体、公共异常、全局错误码、共享事件 DTO 和公共常量。
- 它没有独立启动类和业务端口，因此不能像 `platform-order` 一样单独启动；它的作用是被其他服务依赖，而不是提供业务服务。
- 不应把订单、库存、履约各自不同的状态、业务规则和数据库访问逻辑放入其中，否则会造成领域耦合。
- 错误码也要区分范围：全局通用错误码可以放 common，订单库存专属错误码应尽量留在对应领域模块。

### 统一响应与异常处理

- `Result<T>` 统一接口响应的结构，例如状态码、消息和数据，降低客户端与服务联调成本；它不是让所有服务共享业务状态。
- `BizException` 表示可预期的业务失败，例如订单不存在、库存不足，通常转换为明确的业务错误码；系统异常应记录日志并返回通用错误信息，避免暴露内部细节。
- `@RestControllerAdvice` 统一拦截当前服务 Controller 层抛出的异常，不能跨服务拦截其他服务的异常；跨服务错误需要通过 HTTP/Feign 的错误协议和调用方处理。
- 三者配合形成“业务异常可识别、系统异常可兜底、接口格式统一”的服务内异常处理机制。

## Java / JVM

### 基本类型与包装类型

- Java 有 8 种基本数据类型：`byte`、`short`、`int`、`long`、`float`、`double`、`char`、`boolean`。
- 基本类型不是对象，通常直接表示值；包装类型是对应的类：`Byte`、`Short`、`Integer`、`Long`、`Float`、`Double`、`Character`、`Boolean`。
- 包装类型支持对象语义，可以用于泛型，成员变量默认值可以是 `null`，并提供 `valueOf`、`equals` 等方法；基本类型不能直接作为泛型参数。
- 包装类大多是 `final`，不能被继承；“有类的特点”可以作为方向，但不能简单说包装类型主要依靠多态区分。
- 基本类型与包装类型之间可以自动装箱和拆箱；包装类型为 `null` 时自动拆箱可能触发 `NullPointerException`。

### Java 引用与 C 指针

- Java 引用变量保存的是对象的引用，可以理解为“指向对象的受控句柄”；多个引用可以指向同一个对象。
- Java 引用和 C 指针的共同点是都能间接定位一个对象/内存实体，但 Java 不允许对引用做地址运算、指针加减或直接读取内存地址。
- Java 引用受到类型系统和垃圾回收器管理：可以是 `null`，对象不可达后可能被 GC 回收，程序员不需要手动 `free`。
- C 指针可以进行指针运算、直接操作地址，需要程序员管理内存；Java 对底层地址进行了抽象和限制。
- `==` 对引用类型通常比较是否指向同一个对象；`equals()` 用于比较对象逻辑上是否相等，具体取决于类的实现。

### 包装类型缓存与 `==`

- `Integer a = 127` 属于自动装箱，通常通过 `Integer.valueOf(127)` 获取缓存对象，因此两个相同范围内的装箱结果可能引用同一个对象。
- `Integer c = 128` 超出默认缓存范围，通常会创建不同对象，因此 `c == d` 通常为 `false`。
- 对包装类型比较数值应使用 `equals()`，不要依赖 `==`；`==` 比较的是对象身份。
- 常见默认缓存范围是 `-128` 到 `127`；面试时还要知道超出范围不保证引用相同，具体缓存配置和实现可能影响结果。

### 为什么泛型不能使用基本类型

- Java 泛型的类型参数要求是引用类型，`int`、`long` 等基本类型不能直接作为 `T`。
- 泛型代码通常会被类型擦除：没有具体边界时，`T` 在运行时会按 `Object` 处理；基本类型不是对象，不能直接当作 `Object` 引用。
- 标准集合以对象引用为基础保存元素，因此 `List<Integer>` 合法，`List<int>` 不合法；加入 `int` 时由编译器自动装箱为 `Integer`。
- 这也是泛型和数组的区别之一：数组是 Java 语言级结构，运行时知道元素类型，可以直接支持 `int[]`；泛型主要基于引用类型和类型擦除。
- 包装类型带来对象语义、`null` 和泛型兼容性，但会有对象分配或缓存、拆装箱等额外成本。

### 自动拆箱与 `null`

- 包装类型变量为 `null` 时，自动拆箱不会把它变成 `0`，而是相当于调用 `intValue()`、`longValue()` 等方法，因此会抛出 `NullPointerException`。
- 例如 `Integer count = null; if (count > 0)` 会先把 `count` 自动拆箱成 `int`，在拆箱时直接抛异常，条件判断不会完成。
- “默认值”只适用于成员变量或数组元素：`Integer` 默认是 `null`，`int` 默认是 `0`；局部变量必须显式初始化后才能使用。

### String 不可变性

- String 对象创建后内容不能直接修改；拼接、替换等操作通常会创建新对象，并让变量改为引用新对象，原对象保持不变。
- 多个引用可以共同指向同一个 String；某个变量重新赋值只改变该变量的引用，不会改变其他变量。
- 不可变性有利于字符串常量池共享、线程安全、哈希值缓存和安全性；频繁拼接应使用 `StringBuilder`，`StringBuffer` 是带同步的旧方案。

### StringBuilder 与字符串拼接性能

- `String` 不可变，`s += "x"` 不能在原字符串上直接追加；在循环中通常会创建新的 `String`，并把旧内容复制到新对象，可能产生大量临时对象和重复拷贝。
- `StringBuilder` 内部维护可扩容的字符缓冲区，`append` 通常直接写入缓冲区，最后调用 `toString()` 生成结果 `String`，因此适合单线程下的频繁拼接。
- “只创建一个 String”是对最终结果字符串的简化说法；`StringBuilder` 自身是对象，内部缓冲区可能扩容并产生新的数组，`toString()` 也会创建最终字符串。准确结论是显著减少中间 `String` 对象和重复拷贝，而不是绝对只分配一个对象。
- 简单的非循环拼接可能被 Java 编译器优化为临时 `StringBuilder`；真正需要手动使用 `StringBuilder` 的典型场景是循环或大量动态拼接。
- `StringBuilder` 非线程安全、性能通常更好；`StringBuffer` 方法带同步，适合需要线程安全的历史场景，但不能把它当作所有并发拼接问题的自动解决方案。

### String 常量池与 `==`

- 字符串常量池是 JVM 用于复用字符串字面量对象的机制，与线程池完全不同，不负责运行线程。
- `String a = "hello"; String b = "hello";` 中两个字面量通常复用常量池中的同一个对象，因此 `a == b` 为 `true`。
- `String c = new String("hello");` 会显式创建一个新的 String 对象，因此 `a == c` 为 `false`，但内容相同所以 `a.equals(c)` 为 `true`。
- String 内容比较使用 `equals()`；`==` 只适合判断两个引用是否指向同一对象。
