# 学习与实践决策

## 已确认决策

- 学习目标：通过一个业务级 Agent 项目学习 Agent 后端，并服务于 Agent 后端开发工程师求职。
- 学习方式：从业务目标和当前项目问题出发，只学习完成当前阶段所需知识；到真实架构决策点再系统比较候选方案。
- 教学节奏：每次只推进一到两个可执行、可验证步骤；如果用户不了解某个概念，从基础、类比、项目联系和失败场景开始讲解。
- 架构原则：架构必须解决真实约束；不把微服务视为默认或更高级的答案，也不为覆盖知识点强行堆叠多 Agent、RAG、MCP 等技术。
- 记录边界：项目实现、知识掌握评估和面试复习分开；已经运行不等于已经掌握，计划内容不算已经实现。
- 资料原则：Hello-Agents、DeepSeek Harness、pi、LangGraph 等只作为到达具体问题时的参考资料或对照实现。
