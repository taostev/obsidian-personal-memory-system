# 微服务项目对话分工

该项目在同一工作区下使用三个聊天，各自职责不同，不能混用：

- **完成微服务项目聊天（当前聊天）**：只负责手把手修改代码、数据库、配置和项目文档；运行服务、测试、联调并验证结果；推进项目阶段和开发任务；更新 `docs/项目进度.md` 和项目方案。可以做实现所需的简短解释，但不负责掌握度评估。
- **评估掌握聊天**：负责项目相关教学、知识点掌握和掌握度评估；不直接替代完成微服务项目聊天推进开发。
- **Java 八股教学聊天**：主要学习另一个工作区文件夹中的 `javaguide-yuque` 内容；不负责推进微服务项目实现，也不把八股内容混入本项目聊天。

记录归属：

- 项目相关教学与评估记录：`docs/学习进度与掌握度评估.md` 和 `docs/Java后端知识学习记录.md`，由“评估掌握聊天”维护；本聊天不负责掌握度记录。
- 项目实施记录：`docs/项目进度.md` 与项目方案文档，只写代码、配置、测试、运行证据和开发任务。
- Java 八股学习记录：以 `javaguide-yuque` 文件夹及其对应聊天记录为准，不复制进微服务项目文档。
- 三个部分可以互相引用，但不把项目实现记录、项目相关教学记录和独立八股学习记录混为一谈。

本聊天的实施边界：

- 以仓库、交接文档和 `docs/项目进度.md` 为准推进实现。
- 解释只服务于当前改动、测试和联调，不开展掌握度评估。
- 不读取、不整理、不引入 `javaguide-yuque` 八股学习内容。

## 代码辅导方式

- 每次只推进一到两个小步骤，并详细说明要打开哪个文件、修改哪一段、粘贴什么代码、如何运行验证。
- 不能只给任务顺序；必须给出足以直接操作的具体内容，并在小步骤完成后再继续下一步。
- 代码修改时保留必要的简短解释，重点围绕当前项目实现和验证。
